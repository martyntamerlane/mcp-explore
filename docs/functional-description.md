# Functional Description — mcp-explore

> **Status**: v1 UI shipped 2026-08-25 (see [`docs/specs/2026-08-25-visual-identity.md`](specs/2026-08-25-visual-identity.md), extending [`docs/specs/2026-08-24-initial-design.md`](specs/2026-08-24-initial-design.md)); the radial graph was replaced by the flow view the same day (see [`docs/specs/2026-08-25-flow-view-design.md`](specs/2026-08-25-flow-view-design.md)). This describes actual behaviour — update it in the same change as any feature work.

## Concept

A public, shareable web page. A user inputs the URL of their MCP server; the page connects directly from their browser and displays the server's tools, resources, prompts, and capabilities as an interactive graph — pleasing and simple.

## v1 features (built)

- **Landing screen** (`ConnectScreen`) — hero copy (including a one-line MCP gloss for newcomers), a server URL input, and a collapsed "Add headers" disclosure that reveals repeatable name/value rows for custom headers (e.g. `Authorization: Bearer …`) plus a "Remember headers on this device" opt-in. A recent-servers list (localStorage, `mcp-explore:recents`) offers one-click reconnect, only persisting headers when the user opted in at save time. "Try the demo" connects to the built-in in-page `demo-issue-tracker` server (4 tools, 2 resources, 2 prompts) over an `InMemoryTransport` — no network involved.
- **Connection + diagnostics** — Streamable HTTP with automatic fallback to legacy HTTP+SSE, via the official MCP SDK; only `http:`/`https:` URLs are accepted. On failure, a **connect-error panel** names the failed transports, explains the browser CORS requirement with the exact headers to add (`Access-Control-Allow-Origin`, `Access-Control-Allow-Headers`, `Access-Control-Expose-Headers: mcp-session-id`), notes the localhost local-network permission prompt, and offers a collapsed "Technical details" dump of the raw per-transport errors.
- **Flow view** (`FlowView`) — a deterministic left→right signal-flow diagram: server node (name, version, transport) on the left, hairline traces flowing right into three capability clusters. Cluster headers use canonical protocol terms with counts (`TOOLS · 12`) and a plain-language gloss beneath (*actions it can perform* / *data it exposes* / *ready-made instructions*) so newcomers understand without renamed concepts or tours. Items are always-readable pills with **adaptive density**: clusters of ≤ 8 items show wide pills (name + one-line description); larger clusters show compact name-only pills in wrapped columns. Clusters over 14 items preview the first 14 with a "+ N more" expander; an active filter bypasses the cap so matches can never hide behind it. A fixed **readout strip** along the bottom prints the hovered/focused item's full one-liner (never a cursor-chasing tooltip). No pan or zoom — fit-to-width with vertical scroll, plus per-cluster collapse. The filter box makes non-matches recede (fade + desaturate + slight shrink; never hidden). Pills are keyboard-operable buttons, shape-and-colour coded by kind (circle = tool, rounded square = resource, diamond = prompt) so colour is never the only signal. **Motion**: still at rest except a quick heartbeat pulse sweeping the traces every ~3 s and the server core's slow breathing; one-shot responses to hover/select; a single connect ceremony (traces draw in, clusters materialize); all motion disabled under `prefers-reduced-motion`. Visual language per the flow-view spec's majesty amendment and 2026-08-26 refinement: gate-ring server core, entity-gradient conduits, kind-tinted pills.
- **Detail panel** (`DetailPanel`) — slides in on pill click, content staggering in (~20 ms per element). Tools show an arguments table (name, type, required marker, description, enum chips, default value) derived from the JSON Schema; types render newcomer-friendly ("text", "list of text", "true / false") with the raw protocol type beneath. Resources show URI/mime type/description with a "Load contents" button that fetches on demand and renders text (pretty-printed if JSON), images (`data:` URI), or a "binary contents" notice; the fetch is not automatic. Prompts show their argument list. Every entity has a **raw JSON disclosure ladder** — collapsed `<details>` that renders the full object with a copy button only once opened, so the closed state never dumps untrusted JSON into the DOM.
- **Overview header** — server name (monospace), a `v{version}` chip, and a transport chip (`streamable-http` / `sse` / `in-memory`); a Disconnect button tears the connection down and returns to the landing screen. (Counts live only in the cluster headers.)
- **Shareable URLs** — connecting via a typed/recent URL writes `?server=<encoded url>` to the address bar with `history.replaceState`; loading that URL auto-connects. Auth headers are never persisted to the URL — only the server URL is encoded. Disconnecting clears the query string back to the bare path.

## Dune mode (easter egg)

A hidden alternate theme, originally specced in [`docs/specs/2026-08-24-dune-mode-design.md`](specs/2026-08-24-dune-mode-design.md) and visually redesigned per [`docs/specs/2026-08-26-dune-cinematic-redesign.md`](specs/2026-08-26-dune-cinematic-redesign.md). Entering the shortened Konami code (`↑↑↓↓←→` — arrows only, trimmed from the classic 10-key code on 2026-08-26) anywhere on the page toggles a full-session fluorescent teal/green reskin (persisted in `localStorage`, `mcp-explore:dune-mode`) — the landing screen, graph, and detail panel all pick up the alternate CSS tokens with no component code changes, since every color already flows through `var(--…)` custom properties. While active, the page background becomes a cinematic scene: an AI-generated planet-limb-at-sunrise image, color-graded fluorescent, kept alive by a slow perpetual camera zoom, pointer-tracking depth parallax across five layers, a deterministic seeded starfield with staggered twinkling, a breathing sun flare, drifting atmosphere haze, a periodic shooting star, and animated film grain. All motion is CSS/JS transforms with a `prefers-reduced-motion` fallback to a still frame. A legibility scrim sits behind the centered connect form, where the image's sun would otherwise wash out the UI. Entering the sequence again toggles it off. (The former procedural heighliner scene and the click-triggered URL-seeded ship departure were removed in the redesign; a connect animation is deferred until the still scene is settled.)

Built as a fully isolated, self-mounting module (`src/dune/`) loaded via its own Vite entry script — see Architecture Overview for the module map and isolation rationale.
