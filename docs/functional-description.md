# Functional Description — mcp-explore

> **Status**: redesigned 2026-08-29 per [`docs/specs/2026-08-29-tool-first-workspace.md`](specs/2026-08-29-tool-first-workspace.md), then tightened the same day by [`docs/specs/2026-08-29-visual-system-tightening.md`](specs/2026-08-29-visual-system-tightening.md) (type/space scale, one segmented control, one row shape, the result under the Run button, the landing's priority corrected) — tools are the subject, one click runs a tool, tools with arguments get a generated form, and the connected view is a permanent browse column plus a permanent workspace. That spec supersedes the deck body of the 2026-08-26 luminous-deck redesign, the rail browser (2026-08-27) and the console drawer (2026-08-27); each of those files carries a banner saying what still stands. The luminous identity, the two-door landing and dark mode carry forward. This describes actual behaviour — update it in the same change as any feature work.

## Concept

A public, shareable web page. A user inputs the URL of their MCP server; the page connects directly from their browser and displays the server's tools, resources, prompts, and capabilities as an interactive graph — pleasing and simple.

## Features (built)

- **Landing — two doors** (`ConnectScreen`) — hero copy (including a one-line MCP gloss for newcomers, sized as the footnote it is) above two side-by-side doors, the whole hero centred in the viewport. **Door 1 "Connect your server"** — the primary, and the one carrying the tinted wash, lit hairline and prism motif (corrected 2026-08-29, TODO-19; the demo door held them until then): a one-line sub stating the differentiator, URL input + Connect, a collapsed "Add headers" disclosure with repeatable name/value rows plus a "Remember headers on this device" opt-in, and a recent-servers list (localStorage, `mcp-explore:recents`) that only persists headers when the user opted in. **Door 2 "Explore a live demo"** — a calm secondary with a neutral button; both doors are left-aligned with the same title/sub/control structure and centre their contents vertically. "Explore the demo" connects to the built-in in-page `demo-issue-tracker` server (6 tools, 7 resources — including path-structured `docs/` and `issues/` files that showcase the rail's folder tree — and 2 prompts) over an `InMemoryTransport`, no network involved. One ambient motion only (a slow canvas-tint drift); the deck is never previewed on the landing, so the power-on stays the first payoff.
- **Connection + diagnostics** — Streamable HTTP with automatic fallback to legacy HTTP+SSE, via the official MCP SDK; only `http:`/`https:` URLs are accepted. On failure, a **connect-error panel** names the failed transports, explains the browser CORS requirement with the exact headers to add (`Access-Control-Allow-Origin`, `Access-Control-Allow-Headers`, `Access-Control-Expose-Headers: mcp-session-id`), notes the localhost local-network permission prompt, and offers a collapsed "Technical details" dump of the raw per-transport errors.
- **One chrome band** — a single 58 px band carries the prism brand mark, `MCP EXPLORE`, a divider, then the server's name, `v{version}` chip and transport chip, with the filter box, mode toggle and Disconnect on the right. There is no second header and no boundary card: the connected view is the band, a browse column, and a workspace.
- **The browse column** (`BrowseColumn`, left, 300 px) — a **Home** control above a segmented control (`Tools 6 · Resources 7 · Prompts 2`) showing one kind's list at a time. Rows are monochrome at rest — hollow entity glyph (circle / square / diamond), name in the identifier face, and for tools a `read only` badge when the server sets `readOnlyHint`. Folders and leaves share one row shape (a folder recedes by fill, not by dropping the card), so a resource-heavy server's list reads as the same app as the tools list. Selecting a row lights it in its kind's accent (filled glyph, tinted edge) and opens it in the workspace; rows never unfold, so the column stays a scannable index at any size. **Resources render as a thresholded folder tree** derived from their URIs (a folder needs ≥ 2 entries; single-child chains collapse to `a/b`; a lone shared scheme is invisible, mixed schemes become top-level folders). Folders are cheap disclosure; several may be open. No preview caps — the column scrolls.
- **The workspace** (`Workspace`, right) — permanent furniture holding exactly one subject, separated from the column by a hairline. It never appears, slides in or overlays; only its contents change, cross-fading in ~160 ms. Subjects: home, a tool, a resource, or a prompt. A subject that vanishes from the snapshot says so rather than going blank.
  - **Home** — the resting subject and the first thing seen after connecting: server name, version, transport, counts, and **the server's own `instructions`** (or an honest line saying it publishes none). Reachable at any time from the column's Home control or by pressing Escape.
  - **A tool** — name, description, then a single column: arguments, the Run control, the result beneath it, and a collapsed raw-JSON disclosure last. The result follows the button down the page rather than sitting in a reserved right-hand column (changed 2026-08-29).
  - **A resource** — name, description, URI · MIME type, then contents (mime-aware pretty-printing, images from base64 blobs, an honest "(binary … — not rendered)" note otherwise, capped at 50,000 chars) sized to a reading width rather than stretched across the viewport. Selecting it is the load request; loads are cached for the session, errors are not, so re-selecting retries.
  - **A prompt** — name, description, an arguments form when it has any, then the returned role-labelled messages. Zero-argument prompts load on selection; parameterised ones wait for **Get prompt**.
- **The Run verb** — **one click runs a tool**. A tool with no arguments runs the moment it is selected, and clicking it again re-runs it. A tool with arguments opens its form; **Run** commits. There is no arming, no confirmation and no undo — including for tools the server never annotated (a deliberate, recorded decision: see the spec's §4.1). While a call is in flight the Run button reads *Running…*; results land in the workspace as sanitized text or pretty-printed JSON (capped at 50,000 chars), errors with a distinct honest treatment and no fake success motion. Results and part-filled forms are retained per tool for the session, so switching subject and returning restores both.
- **Input forms** (TODO-1, shipped scope) — fields are generated from each tool's `inputSchema`: text, number, true/false, one-of (segmented), and comma-separated lists of text. Simple `anyOf`/`oneOf` unions resolve to a real control where there is one honest answer (identical branches; "one or many" of the same scalar, which the list field satisfies; `number | integer`) — deepwiki's `repoName: string | string[]` is a list field, not a JSON box. Anything else — nested objects, arrays of objects, mixed unions — gets a JSON textarea labelled with its raw type, so nothing is silently hidden. Schema defaults prefill; descriptions sit under their label; required fields are marked and **Run stays disabled until they are filled, with the reason stated in plain text beside the button**. Empty optional fields are **omitted** from the call rather than sent as empty strings. Unparseable numbers and malformed JSON block the run with an inline message on the offending field. Prompt arguments use the same fields.
- **Markdown results** (spec [`2026-08-29-markdown-rendering.md`](specs/2026-08-29-markdown-rendering.md)) — much of what real servers return is markdown, and it renders as such: headings, paragraphs, bullet and ordered lists, blockquotes, fenced and inline code, GFM tables, thematic breaks, bold/italic/strikethrough and links. A block is treated as markdown when the server **declares** it (`text/markdown` on a resource) or when the text carries an unambiguous structural signal; a declared `text/plain` or `application/json` vetoes the guess, JSON is never markdown, and a lone `-` or `*` is never enough. Detection is a heuristic over untrusted input, so every rendered block carries a **Show raw** control returning the exact bytes the server sent. Error blocks are always verbatim. Rendering is done by a hand-rolled parser whose output contains no HTML (no `dangerouslySetInnerHTML` anywhere): HTML in the source renders as text, link destinations are allowlisted to `http`/`https`/`mailto` with everything else kept as inert text, links carry `rel="noopener noreferrer nofollow"`, and **remote images are never loaded** — image syntax becomes a link the user may follow, so that viewing a result can't fire a server-chosen tracking beacon. (Resource image *blobs* still render inline as `data:` URIs; those bytes already arrived over the MCP connection.)
- **Filter** — the band's filter narrows the active list by name (not description — names are what servers key tools by), receding non-matches; folders holding a match open automatically, folders with none recede. While a filter is active each segment shows its own hit count, so a match hiding in another kind stays visible. Filtering never changes the workspace's subject.
- **Choreography** — calm 150–250 ms baseline; expressive motion only at the **power-on** (the column's rows ignite in a staggered cascade on connect), the workspace's subject cross-fade, the result settle, and the landing's single ambient drift. At rest the app is still; `prefers-reduced-motion` swaps every entrance for instant states (via `MotionConfig reducedMotion="user"` plus a global CSS floor).
- **Dark mode** (spec 2026-08-27, glows restrengthened 2026-08-29) — follows `prefers-color-scheme` (live) until the user clicks the sun/moon toggle (chrome band when connected; landing top corner), whose choice persists (`localStorage`, `mcp-explore:mode`). A validated luminous-dark token block under `data-mode="dark"`; Dune always wins while active (`:not([data-theme="dune"])` guard). Mode resolves before first paint, so dark-system visitors never see a light flash.
- **Accessibility** — every row and control is a real button; the selected row carries `aria-current`; the workspace is a labelled `aria-live` region so its subject change is announced; run and read states announce through `aria-live`/`role="alert"`. Escape returns to home. Nothing depends on hover: there are no tooltips left in the connected view.
- **Shareable URLs** — connecting via a typed/recent URL writes `?server=<encoded url>` to the address bar with `history.replaceState`; loading that URL auto-connects. Auth headers are never persisted to the URL — only the server URL is encoded. Disconnecting clears the query string back to the bare path.

## Dune mode (easter egg)

A hidden alternate theme, originally specced in [`docs/specs/2026-08-24-dune-mode-design.md`](specs/2026-08-24-dune-mode-design.md) and visually redesigned per [`docs/specs/2026-08-26-dune-cinematic-redesign.md`](specs/2026-08-26-dune-cinematic-redesign.md). Entering the shortened Konami code (`↑↑↓↓←→` — arrows only, trimmed from the classic 10-key code on 2026-08-26) anywhere on the page toggles a full-session fluorescent teal/green reskin (persisted in `localStorage`, `mcp-explore:dune-mode`) — the landing screen, graph, and detail panel all pick up the alternate CSS tokens with no component code changes, since every color already flows through `var(--…)` custom properties. While active, the page background becomes a cinematic scene: an AI-generated planet-limb-at-sunrise image, color-graded fluorescent, kept alive by a slow perpetual camera zoom, pointer-tracking depth parallax across five layers, a deterministic seeded starfield with staggered twinkling, a breathing sun flare, drifting atmosphere haze, muted city-light clusters shimmering in the shadowed cloud band along the planet's surface, a periodic shooting star, and animated film grain. All motion is CSS/JS transforms with a `prefers-reduced-motion` fallback to a still frame. A legibility scrim sits behind the centered connect form, where the image's sun would otherwise wash out the UI. Entering the sequence again toggles it off. (The former procedural heighliner scene and the click-triggered URL-seeded ship departure were removed in the redesign; a connect animation is deferred until the still scene is settled.)

Built as a fully isolated, self-mounting module (`src/dune/`) loaded via its own Vite entry script — see Architecture Overview for the module map and isolation rationale.
