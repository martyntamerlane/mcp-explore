# Functional Description — mcp-explore

> **Status**: redesigned 2026-08-26 per [`docs/specs/2026-08-26-luminous-deck-redesign.md`](specs/2026-08-26-luminous-deck-redesign.md) — light-first "luminous precision" identity, the control-deck stage (replacing the 2026-08-25 flow view), a scoped Run verb, and the two-door landing. Amended 2026-08-27 per [`docs/specs/2026-08-27-rail-browser-redesign.md`](specs/2026-08-27-rail-browser-redesign.md) (resources/prompts became a self-contained browser with in-place unfold) and [`docs/specs/2026-08-27-console-drawer-dark-mode.md`](specs/2026-08-27-console-drawer-dark-mode.md) (the detail panel retired into a bottom console drawer; dark mode added). This describes actual behaviour — update it in the same change as any feature work.

## Concept

A public, shareable web page. A user inputs the URL of their MCP server; the page connects directly from their browser and displays the server's tools, resources, prompts, and capabilities as an interactive graph — pleasing and simple.

## Features (built)

- **Landing — two equal doors** (`ConnectScreen`) — hero copy (including a one-line MCP gloss for newcomers) above two side-by-side doors. **Door 1 "Connect your server"**: URL input + Connect, a collapsed "Add headers" disclosure with repeatable name/value rows plus a "Remember headers on this device" opt-in, and a recent-servers list (localStorage, `mcp-explore:recents`) that only persists headers when the user opted in. **Door 2 "Explore a live demo"**: the more inviting of the two (tinted wash, lit hairline, prism motif) — "Explore the demo" connects to the built-in in-page `demo-issue-tracker` server (6 tools, 7 resources — including path-structured `docs/` and `issues/` files that showcase the rail's folder tree — and 2 prompts) over an `InMemoryTransport`, no network involved. One ambient motion only (a slow canvas-tint drift); the deck is never previewed on the landing, so the power-on stays the first payoff.
- **Connection + diagnostics** — Streamable HTTP with automatic fallback to legacy HTTP+SSE, via the official MCP SDK; only `http:`/`https:` URLs are accepted. On failure, a **connect-error panel** names the failed transports, explains the browser CORS requirement with the exact headers to add (`Access-Control-Allow-Origin`, `Access-Control-Allow-Headers`, `Access-Control-Expose-Headers: mcp-session-id`), notes the localhost local-network permission prompt, and offers a collapsed "Technical details" dump of the raw per-transport errors.
- **The control deck** (`DeckView`, the default stage) — a hairline-bordered **server boundary** (the future multi-server seam) whose header carries the prism emblem, server name, `v{version}` chip, transport chip, and the filter box. Inside: **tools as a central grid of buttons** with the **rail browser on the right flank** (below) — entity glyph (circle), mono name, runnable state visible at a glance. Canonical section headers with counts (`TOOLS · 6`) and 11 px glosses (*actions it can perform* / *data it exposes* / *ready-made instructions*) are retained. Sections over their preview cap (24 tools / 10 top-level rail rows) show "+ N more" expanders; an active filter bypasses the caps and makes non-matches recede across all three kinds (matching on names only, not descriptions — deliberate, names are what servers key tools by). **Adaptive emphasis**: servers with ≤ 4 tools get a compact centered grid and a widened rail instead of a vast empty centre. Hovering a tool button shows a calm **anchored tooltip** (fixed below the element, never cursor-chasing; visible on hover and keyboard focus only — ISSUE-2) with its one-line description; a small `i` icon opens the console drawer without running. Duplicate ids are deduped (first wins). Deterministic layout; still at rest.
- **The rail browser** (`Rail`, spec 2026-08-27, right flank since the console-drawer amendment) — resources and prompts as a self-contained browser; rail rows never open the drawer and have no tooltips. **Resources render as a thresholded folder tree** derived from their URIs (a folder needs ≥ 2 entries; single-child chains collapse to `a/b`; a lone shared scheme is invisible, mixed schemes become top-level folders; flat URIs stay flat rows). Folders are cheap disclosure (several may be open; a count sits on the row); an active filter forces folders open and recedes folders with no matching descendants. **Clicking a row unfolds it in place — unfold is the load request** (accordion: one open leaf per rail): resources fetch their contents immediately and render them inline (mime-aware pretty-printing, images from base64 blobs, an honest "(binary … — not rendered)" note otherwise, size-capped at 50,000 chars), with description and URI + mime as quiet metadata; zero-argument prompts fetch and show their actual role-labelled message text; parameterised prompts list their arguments (required marker, description) with an honest *fill-in preview — coming with tool forms* line. Loads are cached for the session (errors are not, so re-unfolding retries); read errors land with the same honest treatment as run errors. Full keyboard parity (rows are buttons, `aria-expanded`, results in an `aria-live` region).
- **The Run verb** (scoped TODO-1 slice) — click semantics per tool class: tools hinted read-only (`readOnlyHint: true`) and runnable **run on a single click**; runnable tools without the hint use **arm-then-fire** (first click charges the button with a ~150 ms light sweep and the label becomes "Run *name* ▸"; the second click fires; Esc, clicking elsewhere, scrolling, opening the drawer, or a 4 s timeout drains the light back out; exactly one tool can be armed). Tools whose schema has required arguments are **input-required**: a visually distinct face (dashed hairline, "needs input" tag, no run affordance) that opens the console drawer, which states honestly that *inputs required — running these is coming*. Eligibility: every demo-server tool, plus any tool on any server with no required arguments. While a call is in flight the button's edge light circulates; results land in the console drawer as sanitized text/pretty-printed JSON (size-capped at 50,000 chars), errors with a distinct honest treatment — no fake success motion. Full keyboard parity: Enter arms, Enter fires, Esc disarms; armed state is surfaced via `aria-pressed` and a live label change.
- **Console drawer** (`ToolDrawer`, spec 2026-08-27 — replaces the right slide-in `DetailPanel`) — the tools' deep-dive surface, docked inside the server boundary's bottom edge. It **pushes the deck body up, never overlays** (the app has no overlays at all now); opens on a tool's `i` icon, on any run firing, or on an input-required face; holds one tool at a time (selecting another swaps content in place); closes via ✕ or Esc, where Esc first disarms an armed tool and only then closes. Fixed height ≈ a third of the deck, content in wide columns: identity + description + the **raw JSON disclosure ladder** (collapsed `<details>` with a copy button, rendered only once opened) | arguments table (name, type, required marker, description, enum chips, default value; types render newcomer-friendly — "text", "list of text", "true / false" — with the raw protocol type beneath) | RUN section (idle hint / in-flight / result / honest error states).
- **Choreography** — calm 150–250 ms baseline; expressive motion only at: the **deck power-on** (boundary settles, grid ignites in a staggered cascade, rail follows — one-shot per connect, under ~1.5 s), the arm/fire/result loop, the drawer's single ~250 ms rise, expander and unfold reveals, and the landing's single ambient drift. At rest the app is still; `prefers-reduced-motion` swaps every entrance and loop for instant states (via `MotionConfig reducedMotion="user"` plus a global CSS floor).
- **App chrome** — a slim header with the prism brand mark, the mode toggle, and a Disconnect button; server identity lives in the deck boundary, not the chrome.
- **Dark mode** (spec 2026-08-27) — follows `prefers-color-scheme` (live) until the user clicks the sun/moon toggle (app header when connected; landing top corner), whose choice persists (`localStorage`, `mcp-explore:mode`). Implemented as a validated luminous-dark token block under `data-mode="dark"` — same hue families, glowing hairlines on a near-black cool canvas; `-bright` companions genuinely brighter than fills (on light they are deep). Dune always wins while active (the dark block carries a `:not([data-theme="dune"])` guard). Mode resolves before first paint, so dark-system visitors never see a light flash.
- **Shareable URLs** — connecting via a typed/recent URL writes `?server=<encoded url>` to the address bar with `history.replaceState`; loading that URL auto-connects. Auth headers are never persisted to the URL — only the server URL is encoded. Disconnecting clears the query string back to the bare path.

## Dune mode (easter egg)

A hidden alternate theme, originally specced in [`docs/specs/2026-08-24-dune-mode-design.md`](specs/2026-08-24-dune-mode-design.md) and visually redesigned per [`docs/specs/2026-08-26-dune-cinematic-redesign.md`](specs/2026-08-26-dune-cinematic-redesign.md). Entering the shortened Konami code (`↑↑↓↓←→` — arrows only, trimmed from the classic 10-key code on 2026-08-26) anywhere on the page toggles a full-session fluorescent teal/green reskin (persisted in `localStorage`, `mcp-explore:dune-mode`) — the landing screen, graph, and detail panel all pick up the alternate CSS tokens with no component code changes, since every color already flows through `var(--…)` custom properties. While active, the page background becomes a cinematic scene: an AI-generated planet-limb-at-sunrise image, color-graded fluorescent, kept alive by a slow perpetual camera zoom, pointer-tracking depth parallax across five layers, a deterministic seeded starfield with staggered twinkling, a breathing sun flare, drifting atmosphere haze, muted city-light clusters shimmering in the shadowed cloud band along the planet's surface, a periodic shooting star, and animated film grain. All motion is CSS/JS transforms with a `prefers-reduced-motion` fallback to a still frame. A legibility scrim sits behind the centered connect form, where the image's sun would otherwise wash out the UI. Entering the sequence again toggles it off. (The former procedural heighliner scene and the click-triggered URL-seeded ship departure were removed in the redesign; a connect animation is deferred until the still scene is settled.)

Built as a fully isolated, self-mounting module (`src/dune/`) loaded via its own Vite entry script — see Architecture Overview for the module map and isolation rationale.
